## Findings

### SEC-F-001 — Dev dependency `happy-dom` contains three known CVEs

| Field | Value |
|---|---|
| **Severity** | Medium (dev-only; no production exposure) |
| **Category** | dependency |
| **File** | `package.json` line 27 |
| **Reproducible** | true |

**Description:**  
`happy-dom@15.11.7` (installed) is within the affected range of three published CVEs:

| Advisory | Severity | Affected Range | Title |
|---|---|---|---|
| GHSA-37j7-fg3j-429f | Critical | `< 20.0.0` | VM Context Escape → Remote Code Execution |
| GHSA-6q6h-j7hj-3r64 | High | `>=15.10.0 <=20.8.7` | Unsanitized export names interpolated as executable code |
| GHSA-w4gp-fjgq-3q4g | High | `< 20.8.9` | fetch credential leak (page-origin cookies sent to wrong target) |

**Evidence:**  
`npm audit` reports 1 critical vulnerability in `happy-dom`, range `<=20.8.8`. Installed version `15.11.7` falls within all three affected ranges.

**Exploitability assessment:**  
`happy-dom` is a `devDependency` used exclusively in `vitest` component tests. It is not bundled into the production build and does not execute at runtime. The test suite renders entirely from deterministic, schema-validated fixture data — no user input, no network fetch, no evaluated module exports. The RCE and cookie CVEs require attacker-controlled inputs to the DOM environment; none are present. The exploit surface is limited to the local development environment during `npm test`.

**Recommended action:**  
Upgrade `happy-dom` to `^20.11.15` in `devDependencies`. This is a major-version bump (`15.x → 20.x`) — verify there are no breaking API changes in the test setup file or component test imports before upgrading. The fix does not require application source changes, only `package.json` and `package-lock.json`.

## Checks: No Issues Found

### Authentication and Authorisation
No routes, API endpoints, server actions, or authenticated resources. The application is a static read-only workspace with no user sessions. N/A.

### Input Validation
No user-supplied input is processed. All rendered content originates from `loader.ts`, which validates all fixture JSON through Zod wire schemas (`WireSchema.parse()`) before any field is accessed. Zod enforces type, enum, and range constraints at the boundary. No raw `as` type assertions on untrusted data.

### Output Handling
- No `dangerouslySetInnerHTML` anywhere in the codebase.
- All content is rendered as React text nodes or JSX elements — React's default XSS escaping applies.
- `DiffPane.tsx` renders line content via `{content}` (text node) and `{token}` (text node inside `<mark>`) — no HTML injection possible.
- `FindingsPane.tsx` renders all fields as `{text}` nodes — `finding.title`, `finding.summary`, `finding.businessImpact`, `item.file`, `item.symbol`, `item.excerpt` are all plain text renders.
- No error messages with stack traces are exposed to the UI.
- No logging of any content.

### Injection Risks
- No SQL, no shell commands, no `exec`/`spawn`, no template engine, no LDAP/XPath/XML.
- `DiffPane.tsx` `renderLineContent()` performs a string `indexOf` search against a hardcoded `EMPHASIS_TOKENS` array — no user input involved.

### SSRF
No outbound HTTP/HTTPS requests anywhere in the application code. No `fetch`, no `axios`, no external URL construction.

### Path Traversal
No filesystem access at runtime. `loader.ts` imports fixture JSON using static ES module imports resolved at build time by Next.js — not by constructing runtime paths from any input.

### Secret Exposure
- No hard-coded API keys, tokens, passwords, or credentials found in any file.
- No `process.env` access in any application file.
- No `NEXT_PUBLIC_` variables in `next.config.ts` or any component.
- `next.config.ts` contains only `reactCompiler: true` — no sensitive configuration.

### Unsafe Configuration
- `tsconfig.json`: `strict: true` is set. ✅
- `next.config.ts`: no `dangerouslyAllowSVG`, no wildcard CORS, no CSP override. No `images` config that relaxes security. The omission of explicit CSP headers is acceptable for a hackathon demo without a deployment target.
- `vitest.config.ts`: `happy-dom` environment is scoped to `app/__tests__` test files only, never loaded in production.
